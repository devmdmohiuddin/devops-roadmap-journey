# Waterfall vs Agile

## Waterfall

The **Waterfall** model is a traditional software development approach where the project is planned and executed in sequential phases.

### Key Characteristics

- Complete planning is done **upfront (A–Z)** before development begins.
- Development follows a **fixed sequence of phases**:
  1. Requirements
  2. Design
  3. Development
  4. Testing
  5. Deployment
- Each phase must be **fully completed** before moving to the next.
- Customer feedback is **costly and difficult** to implement once development has started.
- Projects typically take **6–18 months** to complete.
- Customers, users, or stakeholders usually see the product **only after the entire project is completed**.

---

## Agile

**Agile** is an iterative software development approach that focuses on delivering value continuously through small, incremental releases.

### Key Characteristics

- Breaks the project into **small, manageable chunks of work**.
- These iterations are called **Sprints**.
- Encourages **continuous development** and frequent delivery.
- Customers can provide **feedback at any time**, which is incorporated into future sprints.
- Promotes **collaboration, transparency, and trust** between the development team and stakeholders.
- Enables **faster delivery** of working software.
- Supports **continuous improvement** throughout the development lifecycle.

---

## Waterfall vs Agile Comparison

| Waterfall | Agile |
|-----------|--------|
| Complete planning before development starts | Planning evolves throughout the project |
| Sequential development process | Iterative and incremental development |
| Changes are expensive | Changes are easy to accommodate |
| Customer feedback comes at the end | Continuous customer feedback |
| Product is delivered after full completion | Working software is delivered frequently |
| Typically takes **6–18 months** | Delivers value in short sprints (usually **1–4 weeks**) |
| Less flexible | Highly flexible and adaptive |
